The question

Which architecture is fastest — and cheapest?

Same model, same images, same workload. We vary only the compute strategy and the I/O strategy, then measure. An apples-to-apples harness, not a one-size recommendation.

Finding 01

It's I/O-bound, not compute-bound

GPU inference on all 3,925 images takes only ~50–75s. Writing the annotated JPEGs to the UC Volume is the real cost. Here's where P1's 740 seconds actually go:

75s
write · 635s
GPU inference · ~10% Annotated-JPEG write · 86% Read + overhead
The question isn't "how fast is your GPU" — it's "how fast can you write your outputs." No image output? The bottleneck disappears and the whole ranking changes. Benchmark your workload.

Distributed CPU (P3) finishes 118K in 38 min vs P1's 5h 44m — a 9× gap. Single-node write bandwidth is a hard ceiling; Spark fans writes across an autoscaling pool. Below ~5K → single-node GPU. Above ~100K → distributed CPU.

Findings 04 & 05

Two more things that move the ranking

04 · Layout > total bytes

Imagenette is 20× smaller per file — yet the patterns that lean on directory listing or per-file round-trips got slower on its many tiny nested files:

It's not just how many bytes — it's how many files and how they're laid out.

05 · Serving = direct inference
99.95%
P6 endpoint vs P3 direct inference agreement — just 2 of 3,925 borderline argmax flips (GPU fp16 vs CPU fp32).

A governed, SQL-callable endpoint costs a base64 round-trip and a second compute resource — but not accuracy.

The playbook

When to use what

Small batch (<~5K images) — simplest and cheapest
P2 · P5 — single-node GPU
Large batch (~100K+ images) — needs to autoscale
P3 · P4 — distributed CPU
Want governed, versioned, SQL-callable inference
P6 — ai_query endpoint
Predictions to a Delta table only (no image writes)
Re-benchmark — GPU dominates
A quick baseline or debugging pass
P1 — simplest, most consistent
Also moves the ranking: whether you write images at all · image size & count · parallelism knobs (write-workers, partitions) · soup vs logit ensemble · where the model lives (UC alias, Volume, or endpoint).
The bottom line

Three durable lessons

01
Profile before you optimize. We assumed this was a GPU problem. It was a write problem — inference was under 10% of runtime.
02
Architecture depends on scale. Single-node GPU below ~5K, distributed CPU above ~100K — and the crossover is real, not marginal (9× at 118K).
03
"GPU is expensive" is a myth for the right workload — here it was both faster and cheaper at small scale. Measure, don't assume.
